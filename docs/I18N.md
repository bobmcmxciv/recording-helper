# 多语言架构设计

目标：在不改变"音频不离开手机"的前提下，让录音助手支持中文之外的主要语言（英、日、韩、法、德、西、葡、阿，以及长尾语种），包括三件独立的事：**听懂哪种语言**（转写模型）、**用哪种语言整理**（LLM 输出）、**界面说哪种语言**（UI 本地化）。三者解耦，各自可单独切换。

调研依据见 `_build/research-asr-languages.md` 的来源列表；下文引用的数字均来自其中标注的一手页面，未核实项已注明。

## 一、总体结构

```
┌ 语言偏好（LanguagePreference）──────────────────────────────┐
│ uiLocale（跟随系统或手动） · outputLanguage（纪要/待办语言） │
│ recordingLanguage：auto（语种识别）/ 固定一种 / 每条录音可改    │
└────────────────────────────────────────────────────────────┘
          │                      │                       │
          ▼                      ▼                       ▼
   ASR 路由（LanguageRouter）   LLM 提示模板（按输出语言）   资源本地化（values-xx）
          │
  ┌───────┴────────────┬──────────────────┬──────────────────┐
  ▼                    ▼                  ▼                  ▼
SenseVoiceEngine   SherpaOnnxEngine    CloudAsrEngine     （未来）更多引擎
(LiteRT, 已有)     (ONNX Runtime)      (百炼 / 自定义)
 zh yue en ja ko    Whisper / Parakeet   27 语（百炼）
                    Canary / Nemotron
                    ReazonSpeech / Dolphin
```

原则：
1. **引擎可插拔**：所有引擎实现同一个 `AsrEngine` 接口，上层（队列、实时录音、声纹）只认接口。
2. **模型即"语言包"**：每个可下载的模型是一个 pack，声明自己覆盖的语言、体积、许可、引擎；路由表只做"语言 → 已安装 pack"的查找。
3. **语种识别先行**：auto 模式下先用轻量 LID 判断，再交给对应 pack；识别不出或该语言没有 pack 时，走 Whisper 通用包或云端（需同意）。
4. **一次只驻留一套大模型**：沿用 `ModelGate`，pack 之间串行加载。

## 二、ASR 引擎抽象

```kotlin
interface AsrEngine : Closeable {
    val id: String                       // "sensevoice" / "sherpa-whisper" / "sherpa-parakeet" / "cloud-bailian"
    val languages: Set<String>           // BCP-47 小写：zh, yue, en, ja, ko, fr, de, es, pt, ar …
    val supportsLanguageId: Boolean
    fun transcribe(pcm16k: FloatArray, hint: String?, onPiece: (AsrPiece) -> Unit): AsrResult
}
data class AsrPiece(val start: Double, val end: Double, val text: String, val language: String?)
data class AsrResult(val segments: List<AsrPiece>, val language: String?, val modelMs: Long)
```

- `SenseVoiceEngine`：包装现有 `LocalAsr.Session`，保留 NPU / CPU 选择与崩溃标记逻辑；`language=auto` 时输出语种标签。
- `SherpaOnnxEngine`：接入 sherpa-onnx 的 Android AAR（ONNX Runtime 后端），一个引擎类按 pack 的 `kind`（whisper / transducer / ctc / nemo）构造不同的 recognizer；统一输出分段与时间戳。sherpa-onnx 已提供 Whisper、Parakeet TDT、Canary、Nemotron、ReazonSpeech、Dolphin、Omnilingual 的 int8 包。
- `CloudAsrEngine`：走阿里云百炼 `qwen3-asr-flash`（OpenAI 兼容接口，27 个语码覆盖全部目标语言），复用现有 `LlmSettings` 的同意与密钥框架；音频上传属新的隐私边界，必须单独告知与同意，默认关闭。
- 分段逻辑：固定窗口（SenseVoice 10 秒）与 VAD 切分（Whisper 类 30 秒）由各引擎内部处理；上层只拿分段。

## 四、语种识别与路由

```
录音进入队列 → recordingLanguage 为固定值？ → 是：直接选 pack
                                        → 否：LID
LID 策略（按已安装情况）：
  1. 已装 SenseVoice：前 30 秒走 SenseVoice auto，得到 zh/yue/en/ja/ko/其他
  2. 否则已装 Whisper：用 Whisper 的语种检测（前 30 秒）
  3. 否则：按 uiLocale 猜测，并在详情页提示"识别语言：按界面语言猜测"
结果：
  - 该语言有已安装 pack → 转写，并把语言写入 recording.language
  - 没有 → 用通用包（Whisper）；再没有 → 标记"需要语言包"，详情页给出下载入口或云端选项
混合语言录音（中英夹杂）：优先 SenseVoice（原生混合）；其余按主语言。
```

每条录音保存 `language` 与 `engine`、`pack` 字段，详情页可"用另一语言重新转写"。

## 五、LLM 层

- 提示模板按**输出语言**切换：`prompts/<lang>.json` 保存 system 文本（整理、润色、时段总结三套），JSON 键名保持英文，解析逻辑不变。
- 本地 Qwen3.5 多语言能力可用；在线服务按用户选择。
- `category` 判定词表按语言扩展（work / personal 的同义词表）。
- `DueDates` 改为按 locale 的解析器：相对词（today / tomorrow / 明日 / demain / mañana …）、日期格式（`DateTimeFormatter.ofLocalizedDate` 或各语言的数字日期正则）、一周起始日（`WeekFields.of(locale)`）。写成 `DueDateParser(locale)`，每种语言一组规则加单元测试。
- 待办标题长度限制改为按字形而非字节；阿拉伯语等 RTL 文本用 `BidiFormatter` 包裹后再拼接数字。

## 六、UI 本地化

1. **字符串资源化**：当前界面文案多数写在 Kotlin 里，先把所有用户可见文案迁到 `res/values/strings.xml`（中文为默认），再提供 `values-en`、`values-ja`、`values-ko`、`values-fr`、`values-de`、`values-es`、`values-pt`、`values-ar`。迁移按页面分批，新代码一律用资源。
2. **复数与格式**：数量用 `<plurals>`；日期时间用 `java.time` 的 localized formatter；数字用 `NumberFormat`。
3. **RTL**：`android:supportsRtl="true"`，布局只用 start / end；带方向语义的图标（返回、箭头）用 `autoMirrored`；原文视图对每行调用 `TextUtils.getLayoutDirectionFromLocale` 或 `textDirection="locale"`。
4. **字体**：系统字体覆盖 CJK 与阿拉伯文；不内嵌字体。
5. **语音模型名与许可文本**不翻译；品牌目录名按设备而非语言。
6. **应用内语言切换**：Android 13+ 用 `LocaleManager` 的 per-app locale；低版本用 `AppCompatDelegate.setApplicationLocales`。
7. **看板**：`server/web` 的文案抽成字典对象，按浏览器语言选择；日期用 `Intl.DateTimeFormat`；`<html dir="auto">` 与逐条 `dir="auto"`。
8. **同步协议**：新增可选字段 `language`（recording）；服务端白名单同步放开。

## 七、按语言的首选模型

| 语言 | 端侧首选 | 端侧备选 | 云端兜底 | 说明 |
| --- | --- | --- | --- | --- |
| 中文 / 粤语 | SenseVoice-Small（已有） | Qwen3-ASR-0.6B（体积未核实） | 百炼 qwen3-asr-flash | 中文、粤语优于 Whisper-large-v3 |
| 英语 | Parakeet TDT 0.6B v3 int8（约 671 MB，CC-BY-4.0） | Canary-180M-Flash int8（约 208 MB）；Whisper small / medium | 百炼 | FLEURS en WER 4.85 |
| 日语 | ReazonSpeech k2 v2（Apache-2.0） | SenseVoice-Small；Whisper medium | 百炼 | SenseVoice 的日语弱于 Whisper-large-v3 |
| 韩语 | SenseVoice-Small（已有） | Nemotron 3.5 ASR int8（手机可行性未核实） | 百炼 | 韩语专用小模型稀少 |
| 法语 / 德语 / 西班牙语 | Parakeet TDT 0.6B v3 int8 | Canary-180M-Flash int8 | 百炼 | FLEURS fr 5.15 / de 5.04 / es 3.45 |
| 葡萄牙语 | Parakeet TDT 0.6B v3 int8 | Whisper medium q5_0（约 539 MB，MIT） | 百炼 | 训练数据偏欧葡 |
| 阿拉伯语 | Whisper medium q5_0 | Dolphin small CTC int8（约 250 MB，含阿语，精度未核实） | 百炼 / Azure | 没有经手机验证的阿语小模型；Whisper medium FLEURS ar 20.4 |
| 长尾 | Whisper small / medium | Omnilingual ASR 300M CTC int8（1600+ 语，Apache-2.0） | 百炼 / Azure | 覆盖面优先 |

内存预算（6 GB 机型）：同一时刻只加载一个 pack；Parakeet 与 Whisper medium 不与本地 LLM 同时驻留（`ModelGate` 已保证）。8 GB 以下机型默认推荐 Canary-180M / Whisper small。

## 八、实施顺序

1. **引擎抽象 + sherpa-onnx 接入**（Whisper small 作为第一个新 pack，验证 ONNX Runtime 在联发科 / 高通上的 CPU 表现）。
2. **语言包清单 v2 + 路由器 + LID**；向导"准备模型"步骤改为"选择你的录音语言"，按选择推荐 pack。
3. **LLM 提示模板与 DueDateParser 多语言化**，先英、日、韩。
4. **UI 字符串资源化**，先英语，再按市场顺序补其他语言；看板同步。
5. **云端转写（百炼）**作为可选引擎，复用在线 AI 的同意框架，但独立开关与告知（上传的是音频）。
6. **基准与验收**：每种语言准备 20 条真实场景录音（电话带宽、会议远场），记录 WER / CER、RTF、峰值内存、功耗；阈值：RTF ≤ 0.5（CPU），峰值内存 ≤ 设备内存的 40%。

## 九、风险

- 手机端 Whisper small / medium、Parakeet 的速度与内存没有可引用的一手数据，必须实测；int8 Whisper 有第三方报告的重复 token 问题。
- 许可需逐个核实（Kotoba-whisper 两处许可矛盾；韩语 Zipformer 与 Dolphin 包内 LICENSE 未核实；SenseVoice 权重商用条款未核实）。
- 阿拉伯语方言差异大，MSA 之外效果不保证。
- 字符串资源化会触及几乎所有界面文件，建议在 2.2 单独做一版。
